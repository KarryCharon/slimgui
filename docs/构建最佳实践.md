# slimgui 构建最佳实践

## 发布版本和平台构建

- 每次会进入发布 wheel 的 SlimGUI 修改都要把 `pyproject.toml` 的版本号递增到下一个常规版本；插件按滚动版本选择最新 wheel。
- Release 优化属于 CMake 构建配置：MSVC 使用 `/O2 /DNDEBUG`，其他平台使用 `-O2 -DNDEBUG`，并统一传入 nanobind 的 `NOMINSIZE`，否则 nanobind 会在末尾追加 `-Os` / `/Os` 覆盖前面的优化级别。
- macOS (M2 Max) 实测 `-O2` 相比 `-Os`：文本换行/PrimList 回放约快 30%，`get_render_data_merged` 约快 2.4 倍，Python 调用密集路径约快 3–8%；扩展体积约 +37%（wheel 683 KB → 863 KB）。
- 这类变更通过 `.github/workflows/wheels.yml` 编译，并在发布前检查 wheel 元数据和 ABI 标签。

## 先看项目文档

- 优先阅读 `DEVELOPMENT.md`、`pyproject.toml` 和相关工具脚本，不要直接猜 CMake/Ninja 命令。
- 当前项目的开发入口是 `python tools/gen_bindings.py --full`；只需要编译和生成 stub 时用 `python tools/gen_bindings.py --stubs`。
- 可以用 `uv run python ...` 执行这些入口；需要单独验证 wheel 时用 `uv run python -m build --wheel` 或 `python -m build --wheel`。

## 不要直接依赖旧 build cache

- `cmake --build build/...` 可能引用已经失效的临时 Ninja 路径。
- 如果要验证 native 编译，优先走 `python -m build --wheel` 或 `tools/gen_bindings.py --stubs`，它们会按项目配置准备构建依赖。
- IDE/clangd 的 include path 诊断不一定可靠；真实判断以项目构建入口为准。

## Editable 安装注意事项

- 本项目使用 scikit-build-core 的 editable redirect 模式。
- `src/slimgui/slimgui_ext/*.pyi` 是类型 stub；运行时必须解析到 native `slimgui/slimgui_ext.abi3.so`。
- 不要让 CMake install 根 `slimgui_ext/__init__.pyi` 覆盖 `slimgui.slimgui_ext` 的 native 模块映射，否则会出现 `ImportError: cannot import name 'anim' from 'slimgui.slimgui_ext'`。
- 修改 C++ binding 后，用当前虚拟环境重新执行：

```bash
.venv/bin/python -m pip install -e . --no-build-isolation
```

## 推荐验证顺序

1. 生成/编译/stub：

```bash
uv run python tools/gen_bindings.py --stubs
```

2. 验证 wheel 构建：

```bash
uv run python -m build --wheel
```

3. 验证当前 `.venv` 的运行时导入：

```bash
.venv/bin/python - <<'PY'
from slimgui import anim, imgui, vfx
from slimgui.slimgui_ext import anim as anim_ext, imgui as imgui_ext, vfx as vfx_ext
print("slimgui imports ok")
PY
```

4. 最后再运行示例：

```bash
.venv/bin/python example/anim/gallery.py
```

## VFX 性能基准（调试 gallery 卡顿）

Gallery 有 21 张卡片，整页绘制容易到数毫秒级 CPU 开销。用 headless 脚本单独测 draw-list 构建成本，比盯着窗口 FPS 更容易定位「哪张卡片 / 哪个 VFX 最重」。

**脚本（不随 wheel 发布）：** `tools/bench_vfx_gallery.py`

```bash
# 先确保 native 与当前源码一致
uv run python tools/gen_bindings.py --stubs

# 默认：整页 + 每张卡片各测一轮，输出 mean/median/p95 与 vtx/idx
uv run python tools/bench_vfx_gallery.py

# 导出 JSON 便于对比优化前后
uv run python tools/bench_vfx_gallery.py --frames 240 --warmup 30 --json > bench.json
```

说明：

- 测的是 **CPU 侧构建 ImDrawList**，不是 GPU 上屏；与 `gallery.py` 标题栏的 FPS 互补使用。
- 脚本会优先加载 `build/*/slimgui_ext*.so` 中最新编译产物；若 benchmark 报 `missing native vfx symbols` 而源码里明明有该函数，多半是 `.venv/site-packages` 里的旧 `.so` 没更新，请重新执行 `--stubs` 或 `pip install -e .`。
- 完整说明、输出列含义、常见问题表见 [DEVELOPMENT.md](../DEVELOPMENT.md) 中的「VFX 性能测试」一节。
